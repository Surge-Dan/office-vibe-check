# 《打工人体质检测器》开发计划

版本：v0.1
前置文档：[产品设计文档](../specs/2026-08-19-dagongren-tizhi-detector-design.md)
状态：待执行

## 开发目标

交付一个可以导入小红书官方开发者工具、离线完成测试、生成结果并进行分享的原生小程序工程。

第一阶段不接后端、不接 AI、不做登录和用户数据采集。

## 阶段 0：工程边界确认

### 任务

1. 使用小红书官方开发者工具当前原生模板创建项目。
2. 确认项目配置、页面文件后缀、样式文件格式和分享 API 的实际名称。
3. 确认本地资源路径和包体积限制。
4. 将现有工作区中的原型、压缩包和测试文件与新工程隔离，不覆盖已有文件。

### 验收

- 官方开发者工具可以导入项目根目录；
- 空白首页能够预览；
- 项目不依赖 React、Vue、CDN 或 Node 运行时；
- 实际模板文件名被记录到工程说明中。

## 阶段 1：内容资产落地

### 任务

1. 建立 `data/terms.js`，保存黑话、来源、场景、情绪和风险等级。
2. 建立 `data/types.js`，落地 8 种体质。
3. 为每种体质编写：定义、3 个标签、主要表现、典型场景和至少 5 组结果文案。
4. 建立 `data/questions.js`，落地 7 道场景题和 4 个选项。
5. 为每个选项配置影响的体质及权重。

### 内容验收

- 不出现未经改写的大段网络原文；
- 不出现地域、性别、学历和职业歧视；
- 7 道题不存在明显正确答案；
- 每个结果能够由至少 3 道题共同影响；
- 所有文案长度适合移动端展示；
- 所有题目和文案在断网情况下可读取。

## 阶段 2：核心页面和状态管理

### 页面

1. `pages/index`：首页和上次结果入口；
2. `pages/quiz`：题目展示、选项选择、进度、返回和继续；
3. `pages/result`：体质结果、标签、解释和操作按钮。

### 公共组件

1. `question-card`：题目和选项状态；
2. `progress-bar`：当前题号和进度；
3. `result-card`：结果页和分享卡共用的内容结构。

### 状态要求

- 当前题号；
- 用户答案数组；
- 体质分数对象；
- 结果体质 ID；
- 页面返回后的答案恢复；
- 重新测试时完整清理上一轮状态。

### 验收

- 不能跳过未选择的题目；
- 返回上一题不会丢失已选答案；
- 刷新不会串入上一轮答案；
- 快速连续点击不会重复推进题目；
- 最后一题完成后只生成一次结果。

## 阶段 3：计分和结果生成

### 任务

1. 实现独立的 `utils/scoring` 模块。
2. 对 7 道题的选项分数进行累加。
3. 处理最高分、同分和缺失答案。
4. 通过体质 ID 读取对应结果文案。
5. 将结果统一提供给结果页和分享卡组件。

### 规则

- 单道题不能直接决定结果；
- 同分时使用第 7 题作为决胜题；
- 缺失答案不得静默生成结果；
- 结果只使用本地静态数据；
- 算法函数输入和输出保持纯函数，便于单测。

### 测试

- 每种体质至少有一组可复现答案；
- 同一组答案重复计算结果一致；
- 边界分数和同分场景结果符合预期；
- 非法题号、非法选项和空答案有明确错误处理。

## 阶段 4：视觉和分享卡

### UI 实现

- 使用墨黑、暖白和荧光黄绿作为主视觉；
- 使用“职场档案局”作为统一叙事；
- 首页、题目页和结果页共享编号、细线和标签语言；
- 不使用渐变、玻璃拟态、机器人或 AI 星星；
- 所有点击区域适配移动端触控；
- 保证长标题和小屏设备下不溢出。

### 分享卡

1. 生成 1080×1080 的方形结果卡；
2. 展示体质名、3 个标签、一句原创文案和产品名；
3. 图片内容本地渲染，不依赖远程图片；
4. 接入小红书官方分享回调；
5. 分享失败时保留结果页，不阻断用户继续使用。

### 验收

- 结果卡生成成功率稳定；
- 中文字体、换行和长文案不截断；
- 生成失败时有可理解的提示；
- 分享取消不弹错误；
- 分享后重新进入仍能看到对应结果。

## 阶段 5：真机和平台验收

### 测试矩阵

1. 首页进入、返回和重新进入；
2. 7 道题正常路径；
3. 返回修改、刷新、中途退出；
4. 断网和弱网；
5. 最长体质名称和最长文案；
6. 分享成功、取消和失败；
7. 不同屏幕尺寸和安全区；
8. 首次运行和已有本地结果两种状态。

### 平台验收

- 官方开发者工具预览通过；
- 真机预览通过；
- 上传开发版本通过；
- 体验版链路通过；
- 无未配置域名、无不必要权限、无第三方登录；
- 提交审核前完成文案、资源和隐私检查。

```text

```
