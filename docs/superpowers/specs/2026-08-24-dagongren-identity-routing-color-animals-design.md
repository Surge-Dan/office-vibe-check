# 班味鉴定所：身份路由与彩色动物视觉升级设计

## 背景

现有版本已经支持行业和岗位的两步选择，但标签池仍偏窄，且选择结果只参与少量文案替换，答题路径本质上仍然高度一致。动物报告图案也是单色线稿，无法承载 22 种结果的独立视觉识别。

本次升级一次性解决三个问题：扩大身份覆盖、让岗位真正改变题目路径、用本地彩色插画替换线稿动物。九维度计分底层保持稳定，避免视觉和题库扩充破坏既有结果可比性。

## 目标

1. 将身份选择改为“身份大类 → 行业 → 具体岗位”三步，覆盖主要职业身份并始终提供“其他 / 找不到我的身份”。
2. 将答题题库明确拆成通用基础题、岗位场景题、行业补充题三类，岗位场景优先于行业补充。
3. 在保持 18–21 题总长度、九维度评分、22 种结果和隐藏结果机制的前提下，让不同岗位的用户明显遇到不同工作现场。
4. 将动物从单色镂空线稿升级为 22 套具有完整色彩填充、分层阴影、纹理和配饰的代码原生插画。
5. 页面、Canvas 报告和导出长图复用相同的动物渲染函数，保证视觉一致。

## 非目标

- 不为每个具体岗位建立完整独立测评模型。
- 不改变九个维度的含义和既有结果匹配算法。
- 不使用外部图片、CDN、网络请求或远程字体。
- 不引入自由文本职业输入，避免题目路由不可控和隐私收集。

## 一、三步身份选择

### 身份大类

```text
management    管理 / 带人
professional  技术 / 专业
operations    运营 / 执行
sales         销售 / 客户
content       内容 / 创意
support       支持 / 职能
public        公职 / 国企
student       学生 / 研究
independent   创业 / 自由职业
other         其他 / 暂未匹配
```

### 行业

覆盖互联网科技、金融银行证券保险、财税审计法律、医疗医药健康、教育科研培训、制造工业工程、物流供应链交通、建筑地产能源环保、公职国企公共服务、零售电商消费、餐饮酒店生活服务、创意传媒广告文化、农业生物新消费、学生校园和其他行业。

### 具体岗位

岗位按身份大类维护，并带有可适用行业集合。例如管理类包括基层主管、部门负责人、项目负责人和业务负责人；技术/专业类包括研发工程师、数据算法、产品经理、设计师、工程师、医生、教师、科研人员、财税和法律专业人员；销售类包括销售代表、商务拓展、客户经理、咨询顾问、门店销售和客服；其他身份始终包含暂未匹配选项。

每个岗位携带 `roleFamily`，题目路由按 `roleFamily` 取场景池，而不是为每个岗位复制一套题库。

### 状态和兼容

```js
{
  identityId: 'sales',
  industryId: 'health',
  roleId: 'medical-sales',
  roleFamily: 'sales'
}
```

旧版只有 `industryId / roleId` 时，优先根据旧岗位映射身份大类；无法映射则迁移为 `other / other / other`。非法 ID、空值和篡改值统一回退到安全的“其他 / 暂未匹配”。

## 二、岗位优先的动态题库

题库划分为三类：

| 类型 | 作用 | 路由占比 |
|---|---|---:|
| common | 稳定九维度底层画像 | 12 道基础 + 2 道通用分支 |
| role-track | 贴合具体岗位的真实场景 | 2 道，覆盖 16 个高频岗位 |
| role | 具体岗位没有专属轨道时的岗位族兜底 | 2 道 |
| industry | 补充行业现场压力 | 2 道 |

动态路径固定为：

```text
12 common anchors
+ 2 role-track / role questions
+ 2 industry questions
+ 2 common branch questions
+ 0–2 calibration
+ 0–1 hidden
= 18–21 questions
```

路由优先级为 `role-track > role > industry > common`。先按具体岗位寻找题目，没有专属轨道时再回退岗位族；题目池只负责改变语境，不直接决定体质结果。所有题目都必须是四选一、多维权重、确定性排序、不可重复。

岗位题按岗位族维护：管理、技术专业、运营执行、销售客户、内容创意、支持职能、公职国企、学生研究、创业自由职业。每个岗位族覆盖多个维度，确保销售、产品、医护、教师、制造、财税、内容、公职和自由职业等典型身份能遇到明显不同的场景。

行业题按行业簇维护，每个行业簇 6 道候选题、运行时抽 2 道，覆盖客户拒绝、值班轮班、生产异常、月底结账、家校沟通、流程责任、内容修改和收入波动等现场。行业只做补充，不能覆盖岗位题。通用题不预设互联网、产品或研发场景，避免让非办公室岗位被迫代入错误语境。

## 三、彩色动物插画

采用代码原生 Canvas 的“彩色职场动物档案贴纸”风格，不使用外部位图：

1. 每个结果 code 对应唯一 profile，包括物种、主色、辅色、轮廓、脸部结构、纹理和配饰。
2. 绘制顺序为纸张贴纸底、彩色阴影、动物身体色块、深色轮廓、脸部细节、服饰/道具、颗粒和错位复印纹理。
3. 22 个结果均有独立配色和至少一个可识别特征，不能只靠耳朵角度或眼睛变化伪装成不同动物。
4. 页面头像、报告页头像和导出图都调用 `renderCanvas / drawStamp` 同一套接口。
5. Canvas 不可用时仍显示文字报告，导出失败时保留预览和 Bridge 错误提示。

整体视觉使用蓝、红、酸性黄绿、珊瑚橙、靛紫和薄荷绿作为动物色块，控制在档案纸背景的高对比范围内，避免单色线稿和廉价渐变。

## 四、验收标准

- 三步选择可以完成身份大类、行业和岗位选择；每一步都有其他/未匹配选项。
- 岗位过滤优先于行业过滤；选择销售、技术、医护等岗位时，路由至少包含对应岗位族题目。
- 通用、岗位、行业题目在最终路径中可区分，路径仍为 18–21 题且无重复。
- 10 万条确定性路径全部能完成评分，22 种结果仍可达，分数保持 0–100。
- 22 个动物 code 的 Canvas 输出均包含多个填充色层、阴影或纹理层；页面和导出图调用相同 code。
- ZIP 根目录平铺、无网络依赖、无 Module、无 Worker、无外部资源，最终解压 ZIP 浏览器回归通过。
